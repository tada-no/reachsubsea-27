**The offices map: reuse, don't copy**
- The homepage map lives in `src/blocks/LiveOperations.astro` (about 1,200 lines: markup, MapLibre script, CSS). Its land and camera are built from `src/lib/dot-map.ts` (shared maths: `FRAMES`, `DOT_PRESETS`, `frameBox`, `cameraFor`, `gridPoints`, `maskIndex`) and `src/lib/world-dots.ts` (build time: `landMask()`, `posters(preset)`), with the mask served by `src/pages/data/land-mask.png.ts`. Read those three files and the block's script (`loadMap`, `drawDots`, `updateMarkers`, `fitToShown`, `flyToRegion`) before deciding how to share it.
- Recommended: extract the map itself (poster SVGs + MapLibre camera + dot overlay + HTML markers with clustering + zoom controls + reduced-motion handling) into a shared piece that both blocks use, e.g. a `DotMap.astro` component plus a `src/lib/dot-map-client.ts` module the block scripts import, and leave the Live operations block owning only its status line, filters and region list. Then build a new block, working name **Offices map** (`reach/offices-map`), with the same shape as Live operations: the **list is the content** (an `<ol>` of offices, readable with no JS or CSS), the map is a picture of the list, and its pins are pointer shortcuts to the list rows. Norway's five offices should cluster on the world view and split on zoom, like the region clusters do; cap the zoom at city level (there is no privacy issue here, but a street-level zoom on a dot map is pointless). If extracting turns out to be a much bigger job than the page, say so and propose the smallest safe alternative; don't quietly fork 1,200 lines.
- The map's framing boxes (`FRAMES.wide` 2:1 for desktop and tablet, `FRAMES.tall` 5:4 for phones) already cover every office and presence location; add a frame only if the page needs a different crop, and keep the CSS `aspect-ratio` and the frame aspect in step.
